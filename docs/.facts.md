## Routes & API Surface

All routes are Next.js App Router `route.ts` handlers. Every route file sets `export const runtime = 'nodejs'` and `export const dynamic = 'force-dynamic'` (confirmed per-file).

### Auth model (`core/auth.ts`)

- Sessions are **stateless signed cookies** (HMAC-SHA256), cookie name `sp_session` (`core/auth.ts:10`). TTL 24h (`core/auth.ts:11`, `SESSION_TTL_MS = 1000*60*60*24`). Reset-token TTL 30 min (`core/auth.ts:12`).
- `Role = 'admin' | 'operator'` (`core/auth.ts:14`); `Session { uid, email, role, exp }` (`core/auth.ts:15`).
- Signing key: SHA-256 of `APP_SECRET` env; **fails closed in production** if `APP_SECRET` is unset/short (`core/auth.ts:17-25`) — throws if `NODE_ENV==='production'` and secret <16 chars.
- `signSession()` (`core/auth.ts:29-34`) builds `{uid,email,role,exp}`, base64url-encodes payload, HMAC-signs → `payload.sig` token.
- `verifySession(token)` (`core/auth.ts:36-49`): splits on `.`, recomputes HMAC, **timing-safe compare** (`timingSafeEqual`, `core/auth.ts:42`), checks `exp` not expired and `role` is one of the two valid values (`core/auth.ts:45-46`); returns `null` on any failure.
- `sessionFromReq(req)` (`core/auth.ts:52-56`) — reads/parses the `sp_session` cookie from the raw `Cookie` header and verifies it.
- **`requireRole(req, role?)`** (`core/auth.ts:61-66`): fast, stateless, trusts the token's embedded role for the TTL window.
  - No session → `401 {error:'unauthorized'}` (`core/auth.ts:63`).
  - `role==='admin'` requested but session role isn't admin → `403 {error:'forbidden'}` (`core/auth.ts:64`).
  - Otherwise returns `{session}`.
- **`requireRoleFresh(req, role?)`** (`core/auth.ts:70-78`, async): same as above but **re-checks the DB** — re-fetches the user via `getUserById`, recomputes role live. Used on privileged mutations so a demoted/deleted admin's still-live cookie is rejected immediately.
  - Base check fails → propagates same 401/403.
  - User no longer exists in DB → `401 {error:'unauthorized'}` (`core/auth.ts:74`).
  - `role==='admin'` requested but fresh DB role isn't admin → `403 {error:'forbidden'}` (`core/auth.ts:76`).
- Cookie attributes: `Path=/; HttpOnly; SameSite=Lax` + `Secure` in production + optional `Domain=COOKIE_DOMAIN` (`core/auth.ts:86-90`); `sessionCookie()` sets `Max-Age` = TTL seconds (`core/auth.ts:91-93`); `clearSessionCookie()` sets `Max-Age=0` (`core/auth.ts:94-96`).
- Reset tokens: `makeResetToken()` generates 32 random bytes hex (`raw`), stores only its SHA-256 (`hash`) — raw is emailed, hash persisted (`core/auth.ts:99-105`).
- **Session security boundary**: stateless HMAC-signed cookies are verified in Node route handlers (`core/auth.ts:36-49, 61-66`); edge middleware is explicitly documented as *not* the security boundary (`core/auth.ts:3-5`).

### Edge middleware (`middleware.ts`)

- Runs at the Edge, deliberately **not** importing `core/auth` (keeps the Edge bundle free of `node:crypto`) — re-declares `SESSION_COOKIE='sp_session'` inline (`middleware.ts:3-4`).
- **Coarse gate only**: checks cookie *presence*, not validity/signature (`middleware.ts:6-7`, `12`). The real signature/role check happens in the Node route handlers via `core/auth.ts`.
- Admin subdomain (`host.startsWith('admin.')`) landing on `/` → redirects to `/admin` (`middleware.ts:16-17`).
- Any page request (excluding `/api/*` and the auth pages `/login`, `/reset`) with no session cookie → redirect to `/login?next=<path>` (`middleware.ts:19-23`). **API routes are explicitly excluded from this redirect** — each API route does its own auth via `requireRole`/`requireRoleFresh`.
- Matcher excludes static assets, `manifest.webmanifest`, `sw.js`, and common asset extensions so the PWA files stay publicly reachable without a session (`middleware.ts:27-31`).

### Per-route detail

#### `POST /api/auth/change-password` — `app/api/auth/change-password/route.ts`
- Purpose: logged-in user changes their own password.
- Auth: `sessionFromReq(req)` directly (not `requireRole`) — any authenticated session (`:10-11`).
- Request body: `{ current: string, next: string }` (`:13-14`).
- Errors: no session → `401 {error:'unauthorized'}` (`:11`); `next.length < 8` → `400 {error:'كلمة المرور الجديدة قصيرة (٨ أحرف+)'}` (`:15`); user missing or `verifyPassword(current,...)` fails → `401 {error:'كلمة السر الحالية غلط'}` (`:18`).
- Success: `setUserPassword(u.id, hashPassword(next), false)` then `200 {ok:true}` (`:19-20`).

#### `POST /api/auth/login` — `app/api/auth/login/route.ts`
- Purpose: email+password → issue a signed session cookie. Auth: none (this *is* the login endpoint).
- Request body: `{ email: string, password: string }` (`:15-16`).
- Anti-enumeration: a constant `DUMMY_HASH` (`:11`) is verified against when the email doesn't exist, so `verifyPassword` (scrypt) always runs once regardless — response timing doesn't leak account existence.
- Errors: missing email/password → `400 {error:'الإيميل وكلمة السر مطلوبين'}` (`:17`); user not found or bad password → `401 {error:'الإيميل أو كلمة السر غلط'}` (`:22`).
- Success: `200 {ok:true, user:{email, role, must_change}}` with `Set-Cookie: sp_session=...` header (`:26-28`). Role coerced to `'admin'` only if `u.role==='admin'`, else `'operator'` (`:24`).

#### `POST /api/auth/logout` — `app/api/auth/logout/route.ts`
- Purpose: clear the session cookie. Auth: none required. No request body.
- Response: `200 {ok:true}` with `Set-Cookie` clearing the cookie (`Max-Age=0`) (`:9-11`).

#### `GET /api/auth/me` — `app/api/auth/me/route.ts`
- Purpose: return the current session's identity, or null. Auth: none enforced — `sessionFromReq` (`:9`).
- Response: `200 {user: {email, role} | null}` (`:10`).

#### `POST /api/auth/request-reset` — `app/api/auth/request-reset/route.ts`
- Purpose: email a password-reset link via Resend. Auth: none (public, pre-login flow).
- Request body: `{ email: string }` (`:13`).
- Behavior: **always** returns `{ok:true}` regardless of whether the account exists, to prevent email enumeration (`:2, 23`). If the user exists, generates a reset token, stores its hash (`setResetToken`, best-effort — errors swallowed at `:19`), and emails a reset URL (`sendResetEmail`, best-effort — errors swallowed at `:21`).
- Errors: empty email → `400 {error:'الإيميل مطلوب'}` (`:14`).
- Security note: the reset link's host is **never** derived from the untrusted `Host` header directly — it uses `APP_URL` env if set, else an allow-listed host set (`baw-ai.dev`, `admin.baw-ai.dev`, `scraper-pro-zeta.vercel.app`), else falls back to `https://baw-ai.dev` (`:26-35`) — defends against host-header poisoning stealing the live reset token.

#### `POST /api/auth/reset` — `app/api/auth/reset/route.ts`
- Purpose: consume a reset token, set a new password. Auth: none (token itself is the credential).
- Request body: `{ token: string, password: string }` (`:11-12`).
- Errors: no token or `password.length < 8` → `400 {error:'التوكن وكلمة مرور (٨ أحرف+) مطلوبين'}` (`:13`); token invalid/expired (`getUserByValidResetHash` returns null) → `400 {error:'الرابط غير صالح أو منتهي الصلاحية'}` (`:16`).

#### `POST /api/discover` — `app/api/discover/route.ts`
- Purpose: find product-page URLs from a bare domain, a listing/category page, or a text query (two modes: DOMAIN mode and CATEGORY/query mode). Uses sitemap-first discovery, HTML link harvesting, and optional Firecrawl render fallback for JS-heavy sites.
- Auth: `requireRole(req)` (any role) (`:95`). `maxDuration = 60` (`:16`); internal soft time budget `TIME_BUDGET_MS = 48_000` (`:19`).
- Rate limit: if DB configured, per-user daily counter `discover:{uid}` via `bumpCounter`, cap = `DAILY_DISCOVER_CAP` env or default 150 (`:97-101`). Cap exceeded → `429 {error:'وصلت سقف الأمان اليومي للاكتشاف (${cap})...'}` (`:100`).
- Request body: `{ settings?, limit?: number (default 10, max 20), query?: string, site?: string, url?: string }` (`:103-104, 129, 151`).
- **Query/CATEGORY mode** (when `body.query` non-empty, `:129-148`): calls `searchProductPages(query, site, ...)`, classifies each result page as a listing (≥4 harvested product links → add its products) vs a standalone product page (add the page itself) (`:141-143`). Response: `200 {productUrls: string[], count: number, warnings: string[]}` (`:147`). Empty result adds a warning (no error status) (`:146`).
- **DOMAIN mode** (when no query, uses `body.url`, `:150-187`): missing URL → `400 {error:'a domain or listing URL is required'}` (`:152`); URL fails `assertPublicUrl` (SSRF guard) → `400 {error: <message>}` (`:156`). Pipeline: sitemap-first product harvest (`:160-163`) → scan the given page directly (`:167`) → discover+scan additional listing/shop pages (common paths + `<a href>` heuristics) (`:170-183`). Response: `200 {productUrls: string[], count: number, warnings: string[]}` (`:187`).

#### `POST /api/save` — `app/api/save/route.ts`
- Purpose: push a reviewed manifest through a save adapter (currently `kiss-play`, or client-handled `json`).
- Auth: `requireRole(req)` (any role) (`:15`). `maxDuration = 60` (`:12`).
- Request body: `{ manifest: Manifest, adapter?: string (default 'kiss-play'), storeId?: number | 'env', settings? }` (`:18-20`).
- Errors: `manifest.images` missing/empty → `400 {error:'manifest with images required'}` (`:21`); unknown adapter (not `kiss-play`, not `json`) → `400 {error:'unknown adapter: ${adapter}'}` (`:44`); explicit `storeId` doesn't resolve → `400 {ok:false, error:'الوجهة (المتجر) غير موجودة'}` (`:31`); resolved store has no token → `400 {ok:false, error:'المتجر "${st.name}" ما إله توكن — عدّله بالإعدادات'}` (`:32`).
- Destination resolution logic (`:27-39`): if DB configured and `storeId !== 'env'`: explicit `storeId` → must exist+have token; else falls back to the DB default store if it has a token; else falls through to the legacy `env`/settings-configured store.
- Success/failure passthrough: calls `saveToKissPlay(manifest, s)` → `SaveResult { ok, productId?, productUrl?, error?, duplicate?: boolean }` (defined `adapters/kissplay.ts:9`) — response status is `200` if `r.ok`, else **`502`** (`app/api/save/route.ts:41`). `duplicate` (added `adapters/kissplay.ts:9`) is `true` when the store matched the submitted `source_url` against an existing product instead of creating a new one — `saveToKissPlay()` reads it off the store's JSON response and returns `Boolean(d.duplicate)` (`adapters/kissplay.ts:62`); the store enforces idempotency by `source_url`, this app only surfaces the result. This route has **no code change** for the field — it already forwards the adapter's full result object via `NextResponse.json(r, { status: r.ok ? 200 : 502 })` (`app/api/save/route.ts:41`), so `duplicate` flows through automatically. Still `ok:true`/success, not an error path.

#### `POST /api/scrape` — `app/api/scrape/route.ts`
- Purpose: **the core scraping pipeline** — takes a product URL or free-text search query, extracts/selects/processes images, runs AI enrichment (name/description/tags/price/image-roles), price cross-checks against page evidence, converts price to ILS, probes product videos — streamed to the client as **NDJSON** (not a normal single JSON response).
- Auth: `requireRole(req)` (any role) (`:25`). `maxDuration = 300` (`:20`); internal time budget `TIME_BUDGET_MS = 280_000` (`:22`), leaving headroom under Vercel's 300s hard kill.
- Rate limit: if DB configured, per-user daily counter `scrape:{uid}`, cap = `DAILY_RUN_CAP` env or default 400 (`:29-35`). Cap exceeded → `429` (non-streamed) `{error:'وصلت سقف الأمان اليومي (${cap} عملية سحب)...'}` (`:33`) — a plain `Response`, not NDJSON, since it returns before the stream is constructed.
- Request body: `{ url: string (URL or free-text query), settings? }` (`:38, 44`). Missing/non-string `url` → **(pre-stream)** `400 {error:'url or search query required'}` (`:40`).
- Response on success: `Response` with `Content-Type: application/x-ndjson; charset=utf-8`, `Cache-Control: no-store` (`:257-259`) — body is a stream of newline-delimited JSON objects, one per line, matching the `ProgressEvent` union.
- Client-disconnect handling: listens to `req.signal` abort and the stream's own `cancel()` to set an `aborted` flag that stops further paid provider work mid-pipeline (`:50-57, 160`).
- Pipeline stages emitted as events: source extraction (URL extract or web search) → optional video probing (concurrent with image pool) → image pool selection/ranking → optional AI curation (enrich) → price cross-check against page evidence/JSON-LD → per-image background-removal/processing loop (bounded by time budget, abortable) → guaranteed-result fallback (skips bg-removal if time ran out and nothing processed) → price→ILS conversion → final `result` event with the full `Manifest`.
- In-stream error conditions (sent as `{type:'error', message}` events then the stream closes, still HTTP 200 since headers/status already sent): no candidate image URLs found from extraction/search (`:96-99`); selected image pool has zero usable images (`:112`); all images fail processing and the fallback also fails (`:205`); any uncaught exception in the stream body → `{type:'error', message: <first 300 chars>}` (`:250-251`).

**NDJSON `ProgressEvent` union** (`core/types.ts:59-66`):
```ts
type ProgressEvent =
  | { type: 'stage'; stage: string; detail?: string }
  | { type: 'image'; index: number; total: number; status: 'processing'|'done'|'failed'; detail?: string }
  | { type: 'warn'; message: string }
  | { type: 'cost'; label: string; usd: number; detail?: string }
  | { type: 'result'; manifest: Manifest }
  | { type: 'error'; message: string };
```
- `Manifest` shape (`core/types.ts:38-56`): `{ sourceUrl, pageTitle, name:LocalizedText, description:LocalizedText, price:{amount,currency,confidence,original?}, tags:string[], category, images:ProcessedImage[], videos?:ManifestVideo[], video?:{url,poster?} (deprecated), warnings:string[], createdAt }`.
- Stage values seen in `route.ts`: `'log'`, `'extract'`, `'search'`, `'select'`, `'curate'` (`app/api/scrape/route.ts:59,76,82,110,118`).

#### `GET /api/video-fetch` — `app/api/video-fetch/route.ts`
- Purpose: streaming video **proxy** used as a fallback for the ZIP-download path — the browser first tries a direct cross-origin fetch (free bandwidth); when the source CDN blocks CORS, the client calls this proxy instead. Bytes are piped through, never buffered in memory.
- Auth: `requireRole(req)` — session cookie required (`:18`). `maxDuration = 300` (`:12`).
- Query params: `url` (required) — the upstream video URL to fetch, passed through `assertPublicUrl()` — an **SSRF guard** (blocks private/internal targets) (`:19-23`); `maxMB` (optional) — byte cap in megabytes, clamped `min 5, max 300, default 100` (`:20`).
- Errors: `url` fails `assertPublicUrl` → `400 {error: <message>}` (`:21-23`); upstream fetch throws, is non-ok, or has no body → **`502` `{error:'source fetch failed'}`** (`:29-31`); upstream `Content-Type` is `text/html` (interpreted as a login/bot wall, not real video) → **`502` `{error:'not a video (login wall?)'}`** (`:33-35`); mid-stream, if piped bytes exceed the `maxMB` cap, the stream controller errors (`'size cap exceeded'`) and the stream aborts (`:37-44`) — this terminates the response stream rather than returning a clean JSON error (cap enforced via a counting `TransformStream`).
- Success response: streams the upstream body through with `Content-Type` = upstream's content-type (defaulting to `video/mp4` if absent) (`:32`), `Cache-Control: no-store`, and `Content-Length` forwarded only if known and ≤ the cap (`:46-53`).
- Upstream fetch uses a spoofed desktop `User-Agent` and `Accept: video/*,*/*`, with a 280s abort timeout (`:14-15, 25-28`).

### Cross-cutting notes

- **Auth guard usage summary**:
  - `requireRole` only (no DB freshness check — any logged-in session, role-checked from the token itself): `/api/config` GET, `/api/db-health`, `/api/discover`, `/api/save`, `/api/scrape`, `/api/status`, `/api/stores` GET, `/api/video-fetch`.
  - `requireRoleFresh(..., 'admin')` (admin-only, DB-verified live): `/api/config` POST, `/api/stores` POST/DELETE, `/api/stores/test`, `/api/test`, `/api/users` (all 4 verbs).
  - `sessionFromReq` directly, no role check (any authenticated session, no 403 path): `/api/auth/change-password`.
  - No auth at all: `/api/auth/login`, `/api/auth/logout`, `/api/auth/me`, `/api/auth/request-reset`, `/api/auth/reset`.
- **Error-code conventions observed across routes**: `401` = no/invalid session (or wrong current-password on change-password); `403` = session valid but role insufficient for an admin-gated action; `400` = client input validation failure (missing/malformed body fields, bad URL, SSRF-guard rejection); `404` = target entity not found (`/api/users` PATCH); `409` = conflict (duplicate email on `/api/users` POST); `429` = per-user daily safety cap exceeded (`/api/discover`, `/api/scrape`); `502` = upstream/store call failed or returned unusable data (`/api/save` on adapter failure, `/api/video-fetch` on fetch failure/non-video); `503` = local DB not configured for a feature that requires it (`/api/config` POST, `/api/stores` POST/DELETE, `/api/users` POST); `500` = unexpected server-side exception (`/api/config` POST save failure, `/api/stores` DELETE failure).
- Several routes intentionally return HTTP 200 with an `ok:false`/`error` field in the body instead of a non-2xx status for "soft" failures meant for UI display rather than exception handling: `/api/stores/test` (always 200), `/api/stores` GET on list failure (still 200), `/api/test` (all provider probes reported as 200 rows regardless of individual failure).
- `/api/scrape` and `/api/video-fetch` are the two non-JSON-envelope routes: `/api/scrape` streams NDJSON (`ProgressEvent` lines) at HTTP 200 even when an in-band `error` event is sent; `/api/video-fetch` streams raw video bytes.
- **SSRF guard is applied at every externally-influenced fetch boundary**, not just the initial URL: `core/extract.ts:45-56` (`assertPublicUrl`) is re-invoked for image fetches (`core/extract.ts:341`), video probes (`core/video.ts:80`), Instagram fetches (`core/instagram.ts:34`), and discover-route seeds (`app/api/discover/route.ts:44`) — because search-provider results and page-embedded URLs are all untrusted input.

## Database Schema

Header comment in `core/db.ts:1`: "Neon Postgres: config (encrypted secrets), stores, users, imports" — despite the word "imports," no `imports` table exists in the file; "imports" refers to the *store import* feature (POSTing product data to an external store's `/api/scraper/import` endpoint), not a DB table. Only `core/db.ts` uses the `sql` tagged-template anywhere in the repo (confirmed via repo-wide grep) — it is the single source of DB truth. **No other tables are referenced anywhere in the repo.**

### Connection (`core/db.ts:9-18`)
`DATABASE_URL` env var (`core/db.ts:11`), lazily instantiated via `@neondatabase/serverless`'s `neon()` so a missing var doesn't crash the build (`core/db.ts:5-8`). `dbConfigured()` = `Boolean(process.env.DATABASE_URL)` (`core/db.ts:18`).

### Encryption — AES-256-GCM (`core/db.ts:20-44`)
- Key derivation `keyBuf()` (`:21-28`): SHA-256 of `process.env.APP_SECRET` (falls back to the literal string `'dev-insecure-change-me'` in non-prod). **Fails closed in production**: throws if `NODE_ENV==='production'` and `APP_SECRET` is unset or `<16` chars (`core/db.ts:24-26`).
- `encrypt(plain)` (`:29-35`): random 12-byte IV, `aes-256-gcm`, output format `iv.base64 . authTag.base64 . ciphertext.base64`.
- `decrypt(enc)` (`:36-44`): reverses the above; returns `''` on any parse/verify failure (swallowed try/catch).

### Password hashing — scrypt (`core/db.ts:46-58`)
- `hashPassword(pw)` (`:47-50`): random 16-byte salt, `scryptSync(pw, salt, 32)`, stored as `scrypt.saltB64.hashB64`.
- `verifyPassword(pw, stored)` (`:51-58`): recomputes scrypt hash, constant-time-compares with `timingSafeEqual`.

### `app_config` table (`core/db.ts:60-86`)
**Purpose**: generic encrypted key/value store for provider API keys, admin-editable settings, the app password, and (reused, no separate table) daily usage counters.
**Columns observed**: `key` (PK, text), `value` (text — plaintext or the `iv.tag.ct` encrypted blob), `encrypted` (boolean), `updated_at` (timestamp, set via `now()`).
- `getConfig(key)` — `SELECT value, encrypted FROM app_config WHERE key = ${key}` (`core/db.ts:62`); decrypts if `encrypted`.
- `setConfig(key, value, encrypted)` — upsert: `INSERT ... ON CONFLICT (key) DO UPDATE SET value=..., encrypted=..., updated_at=now()` (`core/db.ts:68-69`). Implies a **unique constraint / PK on `key`**.
- `getAllConfig()` — `SELECT key, value, encrypted FROM app_config` (`core/db.ts:72`), decrypts each row, returns a flat `{key: value}` map.
- `bumpCounter(key, by=1)` (`:79-86`) — **daily safety-cap counters reuse `app_config`**, keyed as `` `ctr:${YYYY-MM-DD}:${key}` `` (`:81`); upserts with `value = (value::int + by)::text` on conflict (`:83`), returns the new integer count. Used by `app/api/scrape/route.ts:31` (key `scrape:${uid}`) and `app/api/discover/route.ts:99` (key `discover:${uid}`) as per-user daily caps.

### `stores` table (`core/db.ts:88-130`)
**Purpose**: multiple save/export destinations ("stores") the scraper can POST finished product data to; the destination auth token is encrypted at rest.
**Columns observed**: `id` (PK, serial/int, `RETURNING id`), `name` (text), `base_url` (text), `token_enc` (text — `encrypt()`'d token, `''` if none), `category_default` (text), `is_default` (boolean).
- `listStores()` — `SELECT id, name, base_url, category_default, is_default, (token_enc <> '') AS has_token FROM stores ORDER BY is_default DESC, id` (`core/db.ts:93-94`) — token value itself never returned, just a `has_token` flag.
- `getStoreResolved(id)` / `getDefaultStoreResolved()` (`:102-107`) — `SELECT id, name, base_url, token_enc, category_default FROM stores WHERE id=... / WHERE is_default=true ORDER BY id LIMIT 1`; `resolveRow()` (`:97-101`) decrypts `token_enc` into a plaintext `token`.
- `upsertStore(i)` (`:108-127`) — trims/validates `name`+`base_url` (required, `:113`), strips trailing slashes from `base_url` (`:110`), defaults `category_default` to `'toys'` (`:111`). If `is_default` is set, first clears any existing default (`UPDATE stores SET is_default=false WHERE is_default=true`, `:114`) — enforces "at most one default" at the app layer, not via a DB constraint. Only re-encrypts/overwrites `token_enc` if a new non-empty token was supplied (`:115-121`), so updates don't require re-sending the secret.
- `deleteStore(id)` — `DELETE FROM stores WHERE id = ${id}` (`core/db.ts:129`).

### `users` table (`core/db.ts:132-183`)
**Purpose**: application auth (admin/operator roles) + password-reset flow.
**Columns observed**: `id` (PK), `email` (text, case-insensitive lookups via `lower()`), `password_hash` (text, scrypt format from `hashPassword`), `role` (text: `'admin' | 'operator'`), `must_change` (boolean), `created_at` (timestamp), `reset_token` (text, nullable — SHA-256 hash of a raw reset token, not the raw token itself), `reset_expires` (timestamp, nullable).
- `getUserByEmail` — `SELECT * FROM users WHERE lower(email) = lower(${email})` (`:135`).
- `getUserById` — `SELECT * FROM users WHERE id = ${id}` (`:139`).
- `listUsers` — `SELECT id, email, role, must_change, created_at FROM users ORDER BY id` (`:143`).
- `countUsers` — `SELECT count(*)::int AS c FROM users` (`:147`).
- `createUser(email, passwordHash, role, mustChange=true)` — `INSERT INTO users (email, password_hash, role, must_change) VALUES (lower(...), ..., ..., ...) RETURNING id` (`:151-152`).
- `setUserPassword(id, passwordHash, mustChange=false)` — `UPDATE users SET password_hash=..., must_change=..., reset_token=NULL, reset_expires=NULL WHERE id=${id}` (`:156`) — clears any pending reset on password change.
- `setUserRole(id, role)` — `UPDATE users SET role = ${role} WHERE id = ${id}` (`:159`) (unguarded variant).
- `deleteUser(id)` — `DELETE FROM users WHERE id = ${id}` (`:162`) (unguarded variant).
- `deleteUserGuarded(id)` (`:166-170`) and `setUserRoleGuarded(id, role)` (`:171-176`) — atomic "keep ≥1 admin" guards: the admin-count subquery is embedded in the mutating statement's `WHERE` clause (`AND (role <> 'admin' OR (SELECT count(*) FROM users WHERE role='admin') > 1)`) so a concurrent check-then-act race can't drop the last admin; return `false` (no row affected) if blocked.
- `setResetToken(id, hash, expires)` — `UPDATE users SET reset_token=..., reset_expires=${expires.toISOString()} WHERE id=${id}` (`:178`).

### FLOW 1 — "Scrape a product URL": `POST /api/scrape` end-to-end

Entry point: `app/api/scrape/route.ts`. `runtime='nodejs'`, `dynamic='force-dynamic'`, `maxDuration=300` (`app/api/scrape/route.ts:18-20`). Internal soft deadline `TIME_BUDGET_MS = 280_000` (`app/api/scrape/route.ts:22`), leaving 20s headroom under Vercel's 300s hard kill for the guaranteed-result fallback + stream flush.

**1. Gate + safety cap**
1. `requireRole(req)` — signed-cookie session check, `app/api/scrape/route.ts:25` → `core/auth.ts:61-66` (`requireRole`), cookie verified via HMAC-SHA256 in `core/auth.ts:36-49` (`verifySession`).
2. Daily per-user run cap: `bumpCounter('scrape:'+uid)` against `DAILY_RUN_CAP` (default 400) — `app/api/scrape/route.ts:29-35`, counter persisted in `core/db.ts:79-86` (`bumpCounter`, reuses `app_config` table keyed `ctr:<day>:<key>`).
3. Body parsed, `input` (URL or free-text query) required — `app/api/scrape/route.ts:37-42`.
4. `resolveSettings(body?.settings)` — `app/api/scrape/route.ts:44` → `core/settings.ts:57-78`; merges client prefs with DB-stored (decrypted) keys then env fallback.
5. `deadlineAt = started + TIME_BUDGET_MS` computed once and threaded into every downstream call — `app/api/scrape/route.ts:47-48`.
6. Client-abort listener sets `aborted=true` so paid provider calls stop being *sent* (best-effort) — `app/api/scrape/route.ts:49-53`.
7. Response is a `ReadableStream` of NDJSON `ProgressEvent`s (`Content-Type: application/x-ndjson`) — `app/api/scrape/route.ts:52-260`, event shapes defined in `core/types.ts:59-66`.

**2. Source branch: URL vs text query**
`isUrl = /^https?:\/\//i.test(url)` — `app/api/scrape/route.ts:43`.
- **URL branch** (`app/api/scrape/route.ts:72-80`): heuristic warn for search/category-looking URLs (`search_result|search_key|/search|category|list.html|goods_list`) — `:73-75`. `extractMedia(url, s, log)` → `core/extract.ts:169-290`.
- **Text-query branch** (`app/api/scrape/route.ts:81-92`) — this *is* Flow 2 (see below).
- Both branches converge on: `candidateUrls`, `pageTitle`, `pageText`, `srcWarnings`, `videoCandidates`, `ldPrice` — `app/api/scrape/route.ts:64-101`. Empty-candidates guard emits `{type:'error'}` and closes the stream — `:95-100`.

**3. Extraction (`core/extract.ts:extractMedia`, called at `app/api/scrape/route.ts:77`)**
1. **SSRF guard**: `assertPublicUrl(pageUrl)` — `core/extract.ts:45-56, 205` — rejects non-http(s), localhost/.local/.internal, RFC1918 ranges, `0.0.0.0`, `::1`, `169.254.169.254` (cloud metadata IP), unless `SCRAPER_ALLOW_PRIVATE=1`.
2. **Instagram fast-path**: if the target itself is an IG post/reel URL (`ig.isIgPostUrl`, `core/instagram.ts:21-28`), `ig.igPostMedia` runs first and its media is added as first-class candidates — `core/extract.ts:207-218`.
3. **URL-param images** (Temu-style `top_gallery_url` in query string) — `core/extract.ts:220-225`.
4. **Plain fetch** of the page with a desktop UA — `core/extract.ts:228-242`; **bot-wall detection** (`!res.ok` or small page + captcha/"just a moment" markers) discards the HTML so Firecrawl escalation actually fires — `:235-239`.
5. **JSON-LD Product/Offer parsing FIRST** — `parseJsonLd` (`core/extract.ts:101-125`), called `:245-247`. This is the **authoritative** image gallery + price source (`ld.images`, `ld.price`).
6. **Generic harvest** — `og:image`/`twitter:image` meta, `<img src|data-src|data-lazy|data-original>`, `srcset`, and a raw `IMG_RE` regex sweep over inline JSON — `harvest()` `core/extract.ts:58-63`, called `:249`. Video harvest in parallel via `harvestVideos()` `core/extract.ts:69-76` (og:video, `<video>`/`<source>`, JSON video fields, raw `.mp4/.webm`).
7. **Firecrawl rendered-fetch escalation** — only if `found.size < 3` and `s.firecrawlKey` set — `core/extract.ts:251-267`; `firecrawlHtml()` POSTs `https://api.firecrawl.dev/v1/scrape` (`:156-167`) with `waitFor:3500`. Re-runs JSON-LD + harvest on the rendered HTML.
8. **Price-candidate mining** from raw HTML (currency-symbol regex, JSON price fields, `itemprop=price`, `product:price:amount` meta) — `extractPriceCandidates()` `core/extract.ts:128-139`, prepended to `pageText` as a `PRICE CANDIDATES:` line (`:271`) — this is what `core/currency.ts:candidateAmounts` later cross-checks against.
9. Pool sizing: `poolSize = min(28, max(maxImages*3, 14))` — `core/extract.ts:274` — deliberately over-fetches so `select.ts` has real signal to rank on.
10. Video output capped to 6 candidates then 3 URLs; HLS-only (`.m3u8`) pages get a warning but no video (no ffmpeg in this stack) — `core/extract.ts:200, 280-287` and header comment `:65-68, 78`.
- Returns `Extraction{ imageUrls, videoUrls, videos, pageTitle, pageText, usedFirecrawl, warnings, ldPrice }` — interface at `core/extract.ts:22-33`.

**4. Concurrent video probe (starts before/alongside image selection)**
`app/api/scrape/route.ts:103-107`: if `s.includeVideos!==false` and candidates exist, `probeVideos(videoCandidates, s, 8000, log)` (`core/video.ts:29-61`) is kicked off as a **non-awaited** promise (`videoTask`) so its ~8s budget overlaps the image-pool download instead of adding to wall time (comment `:103-104`). Awaited later at `app/api/scrape/route.ts:232`.
- `probeVideos` internals (`core/video.ts`): Range-GETs the first 256KB of up to 6 candidates in parallel (`:14-16, 38-41, 79-84`) — bytes are **not** fully downloaded. Detects real container via magic bytes: mp4 `ftyp` box or WebM EBML header — `:92-93`. Parses `moov`/`mvhd`/`tkhd` boxes for width/height/duration via a hand-rolled MP4 box walker (`:120-158`); one extra tail-Range fetch for non-fast-start mp4s (`:103-115`). "Quality-first" policy: inconclusive probes are **kept** as `probe:'partial'`; only definitive non-video responses (HTML/login walls) are rejected — `:5-6, 94-97`. Size cap enforced from `s.maxVideoMB` (default 100 — `core/settings.ts:28,38`) only when size is known — `:44,48`. `rankVideos()` dedupes signed-URL variants of the same file and orders by resolution → bytes → filename resolution hints (`1080/hd/high` > `720`) — `:64-77`. Result type `ManifestVideo` — `core/types.ts:27-36` — carries `probe`, `keep` (review toggle), `source`.

**5. Selection (`core/select.ts:selectPool`, called `app/api/scrape/route.ts:111`)**
1. Parallel download pool, `DOWNLOAD_CONCURRENCY=6`, hard `DOWNLOAD_BUDGET_MS=40_000` — `core/select.ts:22-23, 45-83`, using `fetchImage()` from `core/extract.ts:339-353` (re-applies `assertPublicUrl` and caps buffer size 1KB–15MB, `:341,350`).
2. Per candidate: `sharp().metadata()` for real dimensions; drops <80×80 (icon) and aspect ratio outside `[0.4, 2.5]` (banner/strip) — `core/select.ts:65-69`.
3. **Perceptual dedup**: 8×8 average-hash (`aHash`, `:26-34`) + Hamming distance ≤6 (`hamming`, `:35-39`); on a hit, keeps whichever copy has more megapixels — `:74-77` (only when `s.dedup !== false`).
4. Ranks by `megapixels` desc then `bytes` desc, prefers candidates ≥`MIN_DIM=300` but falls back to the largest available if none clear the bar — `:21, 86-90`.
5. Shortlist capped at `min(10, max(maxImages*2, 6))` — `:89`.
6. `poolThumb(buf, px=448)` — `:97-100` — produces the JPEG thumbnail fed to AI vision; 448px chosen deliberately so watermarks/blur/text are visible to the model (comment `:94-96`).
- Empty-pool guard at `app/api/scrape/route.ts:112`.

**6. AI enrichment (`core/enrich.ts:enrich`, called `app/api/scrape/route.ts:120`)**
Gated on `s.aiEnabled` (`:117`) and a time-budget floor (`remainingMs(deadlineAt) < 10_000` skips, `core/enrich.ts:86`).
1. Thumbnails built via `poolThumb` for every pool candidate, `Promise.all` — `app/api/scrape/route.ts:119`.
2. **Anthropic first** (`s.anthropicKey`, model default `claude-opus-4-8` from `core/settings.ts:33`): `callAnthropic()` — `core/enrich.ts:97-125, 159-194` — POSTs `https://api.anthropic.com/v1/messages` with **structured outputs** (`output_config.format.type='json_schema'`, schema `ENRICH_SCHEMA` `:52-69`) so a malformed response is grammar-impossible on this path (comment `:175-177`). One retry with a higher `max_tokens` (6000) if `stop_reason==='max_tokens'` (truncation) — `:102-107`; one backoff-retry on 429/529 — `:118-122`. Cost computed from the response's own `usage` block against `MODEL_PRICE` table — `:72-74, 184-193` — and streamed via `onCost` → `{type:'cost'}` event.
3. **OpenAI fallback** — reached when Anthropic is unconfigured, errors, or returns an unusable/unparseable response (`sawUnusable` flag) — `:127-145, 196-217` — POSTs `https://api.openai.com/v1/chat/completions` (`model:'gpt-4o'`, `response_format:{type:'json_object'}`), flat $0.02 cost estimate (`:135`).
4. Response `parse()` — `:221-251` — dedupes/bounds-checks image indices (protects against a hallucinated duplicate role being billed/processed twice, comment `:226-227`), tolerates the legacy `price_ils` shape.
5. `hasContent()` — `:149-151` — a parse with **no name in any language** is treated as FAILURE (returns `EMPTY`), not a silent success.
6. System prompt (`SYS`, `:28-48`) fences the scraped page text as `<untrusted_page_text>` and explicitly instructs the model never to follow instructions found inside it (prompt-injection defense) — `:47`.
7. `logSkips()` surfaces the model's one-word skip reasons to the NDJSON log stream — `:153-156`.
- Back in the route: `keepOrder` built from `ai.imageRoles` (skips filtered out, extra `main`s demoted to `angle`) — `app/api/scrape/route.ts:121-129`; capped at `s.maxImages`; falls back to "first image is main, rest angle" when AI is disabled or produced nothing usable — `:115-116, 130-133`.

**7. Price cross-check (`app/api/scrape/route.ts:138-155`)**
- `candidateAmounts(pageText)` — `core/currency.ts:40-49` — regex-mines numeric amounts out of the `PRICE CANDIDATES:` line extract.ts prepended.
- The AI's `ai.price.amount` is **rejected** (set to `null`, warned to the user) if it matches neither the JSON-LD price (`ldPrice`) nor any mined candidate nor the raw page text — `app/api/scrape/route.ts:141-146` — explicit defense against a hallucinated or page-injected price.
- A missing AI price is backfilled from `ldPrice` (structured markup is authoritative) — `:149-152`.
- `priceConfidence` is `'high'` only when AI and JSON-LD numerically agree, else `'low'` — `:154-155`.

**8. Per-image processing loop (`app/api/scrape/route.ts:158-184`)**
For each kept candidate (respecting `aborted` and the `TIME_BUDGET_MS` deadline mid-loop, `:160-164`):
- Watermark removal is **only ever enabled on the `main` image** — `imgS = {...s, removeWatermark: s.removeWatermark && role==='main'}` — `:170`.
- `processImage(c.buf, c.contentType, imgS, log, deadlineAt, cost)` — `core/process.ts:30-122`, called `:171`.
- Emits `{type:'image', status:'processing'|'done'|'failed'}` progress events per image — `:167, 180, 182`.
- Results accumulate into `ProcessedImage[]` (`core/types.ts:5-21`), embedding processed bytes as base64 `dataUrl` — `:172-179`.
- `core/process.ts:processImage` pipeline (Sharp), in order: (1) **Watermark removal** (opt-in) — `removeWatermark(input, s, log, deadlineAt)` — `:41-42` → `core/watermark.ts:104-125`; runs *before* cutout so the bg-removal model sees full context (comment `:40`); success forces `contentType` to `image/png` and logs cost `$0.03`. (2) **Background removal** — `removeBackground(...)` — `:45` → `core/bgremove.ts`. (3) **Trim** transparent border when a cutout exists (`threshold:12`) — `:52-55`. (4) **Canvas geometry**: transparent-only when `cut` exists AND `bgColor` unset/'transparent'; padding clamped 0–40%, letterboxed onto a transparent field first so tone adjustments never tint the padding — `:57-70`. (5) **Tone**: brightness/contrast/sharpen from settings, clamped — `:72-79`. (6) **Solid-bg flatten** applied in a *separate* pass after tone (an in-pipeline flatten previously reordered ahead of tone and tinted the background) — `:81-83`. (7) **Multi-format encode** with byte-cap enforcement: quality steps down by 12 in a loop until under `s.maxKB` (default 400KB, clamped 50–3000) or `quality<=45` — `:87-107`. First requested format is primary; the rest ship as `variants` for the ZIP export. `thumbnailJpeg()` (256px) is a separate small helper for cheap AI vision use elsewhere — `:125-131`.

**9. Watermark removal detail (`core/watermark.ts`)**
Gated: needs `s.removeWatermark`, an Anthropic or OpenAI key, and ≥25s of remaining budget (never *started* into a nearly-spent window) — `:105-108`.
1. **Detect** (vision, bounding box in %): Anthropic preferred (`detectAnthropic`, `:26-39`, POST `api.anthropic.com/v1/messages`), else OpenAI (`detectOpenAI`, `:41-51`, `api.openai.com/v1/chat/completions`). `normBox()` rejects degenerate (<1.5%) or oversized (>80% dim or >35% area) boxes to avoid nuking the whole product — `:17-23`.
2. **Inpaint**: OpenAI `dall-e-2` edits preferred (`openaiInpaint`, `:55-86`, squares the image to 1024, builds a transparent-hole mask over the box, POSTs `api.openai.com/v1/images/edits`, then crops back to original aspect — no baked letterbox). Falls back to a **free local blur-fill** (`localFill`, `:89-101`) on any OpenAI failure or when no OpenAI key.
3. Best-effort contract: any failure anywhere returns `null` and the caller keeps the original image — `:6, 121-124`.

**10. Background-removal provider chain (`core/bgremove.ts:removeBackground`)**
Order for `bgMode==='auto'` — `:42-49`: `[replicate if replicateKey] → [removebg if removebgKey] → 'local' (always) → [openai if allowOpenAIImages && openaiKey]`. Explicit `bgMode` values bypass the ladder and call exactly that provider (`imgly` aliases to `local`) — `:50`.
- Budget guard: any *paid* provider (`provider!=='local'`) is skipped once `remainingMs(deadlineAt) < 8000`, routing straight to the free local model instead of starting a call that can't finish — `:55-58`.
- **Quality gate** `hasRealCutout()` — `:19-26` — requires the returned image to actually decode *and* contain alpha pixels with `min < 128`; a misconfigured provider silently returning an opaque image is rejected and the ladder continues (`:65-68`).
- Cost is booked the moment a provider call actually returns bytes, even if later rejected by the quality gate (comment `:63-64`): `PROVIDER_USD = {replicate:0.006, removebg:0.2, openai:0.08}` — `:30`.
- Provider implementations (`:81-152`): `replicate` (83-110) — official-model endpoint or `owner/model:version`, sync-wait via `Prefer: wait=<n>` header, then fetches the output image URL. `removebg` (113-126) — `multipart/form-data` to `https://api.remove.bg/v1.0/removebg`. `local` (129-131) — delegates to `localCutout()` in `core/localbg.ts` — no network call, no key. `openai` (134-151) — `gpt-image-1` via `https://api.openai.com/v1/images/edits`, `background:'transparent'` — opt-in only ("may refuse adult products," header comment `:6`).

**11. Local ONNX cutout (`core/localbg.ts:localCutout`)**
- Model catalog: `isnet-general-use` (default, 1024px input), `silueta`/`u2netp`/`u2net` (U²-Net family, 320px input) — `:14-35`.
- Model weights auto-download once from GitHub Releases (`danielgatis/rembg`) into `os.tmpdir()/scraper-pro-models/`, atomic write via `.part` + `rename` — `:18-33, 47-54`.
- `onnxruntime-node` (N-API, ABI-stable) session lazily created and cached in-process (`sessionPromise`) — `:37-60`.
- Preprocess: EXIF-correct rotate, resize to model input, per-model mean/std normalization, NCHW float32 tensor — `:76-91`.
- Postprocess: min-max normalize the saliency map, apply a smoothstep contrast curve (`curve()`, thresholds 0.15/0.85) to crush haze/solidify the subject — `:62-69, 98-103`; mask upscaled back to source resolution and joined as the alpha channel — `:105-119`.

**12. Guaranteed-result fallback (`app/api/scrape/route.ts:186-204`)**
If the per-image loop produced **zero** images (e.g., cold-start model download + slow search ate the whole budget) and `bgMode !== 'off'`, the top-ranked pool candidate is reprocessed with `bgMode:'off'` and `removeWatermark:false` — no bg removal, no inpaint — so the user always gets *something* rather than a hard failure. Warns the user explicitly (`:202`). True hard failure only when even this returns nothing — `:205`.

**13. Price → ILS conversion (`app/api/scrape/route.ts:208-230`)**
- An amount with no currency is **never** assumed to be ILS (would silently misprice ~4x if a `$` was missed) — surfaced as a manual-review warning instead — `:211-214`.
- `toILS(amount, currency)` — `core/currency.ts:52-66` — live rates from `https://open.er-api.com/v6/latest/ILS` (`liveRates()`, `:25-35`), 6h in-process cache (`TTL`, `:13`), falls back to a static `FALLBACK` table (`:5-8`) if the API is unreachable so a price is always computable. `¥` is mapped to CNY, not JPY, on purpose (this scraper's real sources are China-side) — `:9-10`.
- An unconvertible/unknown currency drops the amount entirely rather than showing a foreign number mislabeled as ₪ — `app/api/scrape/route.ts:225-228`.

**14. Manifest assembly and emission (`app/api/scrape/route.ts:232-249`)**
- `videos = await videoTask` (the concurrently-started probe) — `:232`.
- `Manifest` built per `core/types.ts:38-56`: `sourceUrl`, `pageTitle`, `name`/`description` (LocalizedText en/ar/he), `price`, `tags`, `category` (defaults `s.category||'toys'`), `images`, `videos`, legacy single-`video` mirror (first kept video, or first raw `videoUrls` entry), aggregated `warnings` (extraction warnings + AI-unavailable/unparseable flag + price warning + a constant `'price_requires_review'`), `createdAt`.
- Emitted as `{type:'result', manifest}` — `:249` — then the stream closes (`:253`).

**15. NDJSON event contract**
`ProgressEvent` union — `core/types.ts:59-66`: `stage` (with a synthetic `stage:'log'` used as the general log line, `app/api/scrape/route.ts:59`), `image` (per-image processing status), `warn`, `cost` (label + measured USD + optional detail, streamed the instant a paid call returns — `:61`), `result` (final manifest), `error`.

### FLOW 2 — "Search by product name": `core/websearch.ts` provider ladder

Entered from `app/api/scrape/route.ts:84` (`searchImages(url, s, log)`) when the input isn't a URL, and from `app/api/discover/route.ts:131` (`searchProductPages`, category mode) for page-level discovery.

**`searchImages()` — specific-product image search**
- **Cache**: 1h warm-lambda `Map` keyed by `provider|instagramSearch|query` — `core/websearch.ts:36-57` — so a re-run of the same query bills no provider again.
- Delegates to `searchImagesUncached()` — `:59-154`.
- Ladder, in order, each gated on `s.searchProvider` (`'auto'|'firecrawl'|'google'|'discovery'|'merge'`) plus key presence:
  1. **Instagram** (optional extra source, OFF by default via `s.instagramSearch`) — runs **in parallel** with whichever provider wins below, via `Promise.race` against a 30s timeout, unioned in afterward by `withIg()` — `:68-91`. Implementation: `instagramMedia()` — `:283-305` — Firecrawl-searches `site:instagram.com`, filters through the strict `isIgPostUrl()` host check (`core/instagram.ts:21-28`), fetches each post's media via `igPostMedia()`.
  2. **Google Vertex AI Search (Discovery Engine)** — gated on `s.googleSaKey`, tried when provider is `'auto'` or `'discovery'` — `:99-107`. `discoveryImages()` (`:247-252`) calls `discoverySearch()` for product **pages**, then Firecrawl-scrapes the top 3 for high-res images (`firecrawlScrapeUrlsImages()`, `:255-277`), unioning Discovery's own best-effort `pagemap` images as fallback. **Quality gate**: an early return of only low-res `gstatic.com`/`googleusercontent.com`/`encrypted-tbn` thumbnails does *not* short-circuit the ladder — kept as `weakDiscovery`, used only if every other provider comes up empty — `:98-107, 140-143`.
  3. **Merge mode** (`s.searchProvider==='merge'`) — runs Discovery AND Firecrawl **independently in parallel** and unions all candidates, deferring quality judgment to the downstream resolution filter + AI curation — `:111-118`.
  4. **Google Custom Search JSON API (CSE)**, image mode — gated on `s.googleCseKey`+`s.googleCseCx`, tried for `'auto'`/`'google'` — `:121-127, 206-218` — direct image URLs, sorted by `image.width*height` descending.
  5. **Firecrawl search** — gated on `s.firecrawlKey`, `'auto'`/`'firecrawl'` — `:130-136, 220-243` — POSTs `https://api.firecrawl.dev/v1/search` for the top 4 result pages' HTML, then harvests images from each via `collectImageUrls()` (`core/extract.ts:82-97`).
  6. If nothing above produced strong results but Discovery returned weak thumbnails, those are used as the last-resort fallback — `:140-143`.
  7. If still nothing, Instagram-only results (if any) are returned — `:145-147`.
  8. Otherwise a localized (Arabic) diagnostic warning naming exactly which provider/key is missing — `:148-153`.

**Google Vertex AI Search client (`core/discovery.ts:discoverySearch`)**
- Default engine constants: project `601004755002`, engine `product-image-search_1785023650361`, location `global` — `core/discovery.ts:16-18` (overridable via `s.discoveryProject/Engine/Location`, settings default mirror at `core/settings.ts:35`).
- Auth: `getGoogleAccessToken(s.googleSaKey)` from `core/googleauth.ts` — `core/discovery.ts:12, 38`.
- `site:` scoping is folded into the query string itself, not a separate API param — `:39-40`.
- POSTs `https://discoveryengine.googleapis.com/v1/projects/{project}/locations/{location}/collections/default_collection/engines/{engine}/servingConfigs/default_search:search` — `:20-26, 43-49`.
- Parses `document.derivedStructData.link` (page URL) and `pagemap.cse_image[0].src` / `pagemap.cse_thumbnail[0].src` (image URL, cse_image preferred as higher-res) — `:57-67`.

**Instagram per-post extraction (`core/instagram.ts:igPostMedia`)**
Escalating ladder, cheapest first — `:31-58`: (1) direct fetch of the post URL (desktop UA) — `:32-42`; (2) `/embed/captioned/` variant (usually served without a login wall) — `:44`; (3) Firecrawl render (`https://api.firecrawl.dev/v1/scrape`, `waitFor:2500`) — last resort, costs a Firecrawl credit — `:46-56`. `igHarvest()` (`:61-85`) un-escapes JSON (`\u0026`, `\/`), extracts `display_url`/`display_src`/`thumbnail_src` (images) and `video_url`/`video_versions[0].url`/`og:video` (reel videos, IG lists highest quality first), filtered to actual IG CDN hosts (`cdninstagram`/`fbcdn`, excluding profile-pic thumbnails) via `isIgCdn()` — `:66`. Caption harvested from `og:title` and fed to the AI prompt as **untrusted** context (`core/websearch.ts:91`, `app/api/scrape/route.ts:91`).

### Candidate ADR topics (grounded in code + inline comments)

**ADR-1: Anthropic-primary, OpenAI-fallback for enrichment and watermark detection.**
Evidence: `core/enrich.ts:1-4` header comment states the division of labor explicitly ("Claude: product copywriting + vision classification. OpenAI GPT-4o: automatic fallback"). The Anthropic path is the *only* one wired to server-enforced structured outputs (`output_config:{format:{type:'json_schema', schema: ENRICH_SCHEMA}}`, `core/enrich.ts:176-177`), which the comment says makes `parse()` failures "impossible on this path" — a stronger reliability guarantee than OpenAI's `response_format:{type:'json_object'}` (`core/enrich.ts:209`), which only guarantees *valid JSON*, not schema conformance. Each provider call is independently try/caught (`core/enrich.ts:97-124` vs `128-142`) so a provider *error* (429/529/timeout/policy refusal) falls through instead of aborting enrichment — the same primary/fallback shape is reused for watermark bounding-box detection (`core/watermark.ts:111`). Rationale to document: Anthropic gives schema-enforced reliability + (at the time of writing) better tasteful copy for a sensitive product category (system prompt explicitly frames this as an "adult (18+) intimate-products store," `core/enrich.ts:28`); OpenAI is kept as a second, independently-billed provider so a single vendor incident/outage/key issue doesn't blank the whole enrichment stage.

**ADR-2: A free local ONNX background-removal fallback always exists.**
Evidence: `core/bgremove.ts:1-7` header: "`local` → U²-Net family ONNX via onnxruntime-node (FREE, no key)". In the `'auto'` ladder, `'local'` is included **unconditionally** — it does not require any key check, unlike `replicate`/`removebg`/`openai` (`core/bgremove.ts:42-49`). `core/localbg.ts:1-6` header: "No API key, no external service. Model auto-downloads once to the OS temp dir." The budget guard only skips *paid* providers under time pressure (`provider !== 'local'`, `core/bgremove.ts:55`) — local is exempt because it costs no network round-trip to start. Rationale to document: guarantees the core value prop (a clean cutout) works with **zero** provider configuration/spend, keeps the "guaranteed-result" contract in `app/api/scrape/route.ts:186-204` meaningfully better than "no bg removal at all," and gives every deployment a working default even before an operator adds Replicate/remove.bg keys — at the cost of GPU-less CPU inference latency and a first-run model download.

**ADR-3: AES-256-GCM encrypted config in Postgres instead of env-vars-only.**
Evidence: `core/db.ts:1` header: "Data layer — Neon Postgres: config (encrypted secrets), stores, users, imports." Encryption implementation at `core/db.ts:20-44` (`encrypt`/`decrypt`, AES-256-GCM, key = SHA-256 of `APP_SECRET`, fails closed in production if `APP_SECRET` is short: `core/db.ts:24-26`). `core/settings.ts:56-77` (`resolveSettings`) resolves every provider key **DB first, then env, then client** — DB values are live-editable and take precedence. `core/settings.ts:97-106` (`saveConfigKeys`) encrypts every key except an explicit `NON_SECRET` allowlist (URLs/ids/senders, `core/settings.ts:54`). Multi-tenant *store* tokens are likewise stored encrypted per-row (`stores.token_enc`, `core/db.ts:88-127`), which an env var fundamentally cannot express (one token per env var, not one per store row). Rationale to document: lets an admin rotate/add provider keys and add/edit multiple destination stores from the admin UI at runtime with no redeploy, while still keeping secrets encrypted at rest in the database (defense if the DB dump leaks) — env vars alone would require a redeploy per key change and cannot model "N stores, each with its own token."

**ADR-4: Hand-rolled Google service-account JWT instead of a library.**
Evidence: `core/googleauth.ts:1-5` header: "Mints a short-lived OAuth2 access token from a service-account key by signing a JWT (RS256) with node:crypto and exchanging it at the token endpoint" — built with only `node:crypto` (`createSign`, `createHash`, imported `core/googleauth.ts:7`), no `google-auth-library`/`googleapis` dependency. Implements the full JWT-bearer flow manually: header/claim construction (`:41-42`), RS256 signing (`:44`), token exchange (`:47-53`), and its own fingerprinted in-process cache (`:27, 36-39`) rather than relying on a library's built-in caching. Rationale to document: this app needs exactly one Google Cloud capability (a Bearer token for Discovery Engine) — pulling in `google-auth-library` (and its transitive dependency tree) into a Vercel Node serverless function purely for that one JWT-bearer exchange adds cold-start/bundle weight the hand-rolled ~50-line implementation avoids, while `node:crypto` is already a zero-cost built-in.

**ADR-5: Store-side video download (bytes never transit this app) instead of proxying.**
Evidence: `core/video.ts:6-8` header: "Video BYTES never transit this server at scrape time — the store downloads them server-side at save, and the ZIP downloads them in the browser." The probe stage only Range-fetches 256KB headers (`core/video.ts:82`), never the full file. `adapters/kissplay.ts:36-37` comment: "the STORE downloads these server-side into its own R2 — bytes never transit this tool (Vercel body limits make base64 video impossible)"; the payload carries only `{url, poster_url, width, height, bytes, content_type}` (`adapters/kissplay.ts:38-40`), never video bytes. The save-adapter fetch timeout is deliberately widened to 280s specifically to give the store time to do that download (`adapters/kissplay.ts:57-59`). Rationale to document: Vercel serverless functions have hard request/response body-size limits that make multi-MB video impractical to proxy through this app as base64 JSON; routing bytes through here would also double network egress (fetch once here, re-upload once to the store) and hold a Node function open for the full transfer. Making the store fetch directly from the source CDN is both a hard platform constraint (body size) and a cost/latency optimization (single egress hop, no base64 inflation).

**ADR-6: Perceptual-hash dedup instead of exact-URL dedup.**
Evidence: `core/select.ts:1-4` header: "Cheap pre-filter that runs BEFORE the expensive background removal, so we only process the highest-resolution, non-duplicate candidates." `aHash()` (8×8 greyscale average-hash, `core/select.ts:26-34`) + `hamming()` distance ≤6 (`:35-39, 75`) drive the dedup, applied to **downloaded pixels**, not URLs. The comment at `core/select.ts:72-73` states the explicit failure mode this avoids: "arrival order must not let a 300px thumbnail permanently evict its own 2000px original" — dedup must keep the *best* copy regardless of which URL variant was seen first. A separate, cheaper URL-shape dedup already exists earlier in the pipeline for literal same-family variants (`baseKey()` strips `_400x400`/`-800x800`/`_600w`-style CDN suffixes before comparing, `core/extract.ts:40-42`), but that's a heuristic string match, not content-aware. Rationale to document: the scraper's real-world sources (Temu/AliExpress-class sites, per `core/extract.ts:132`) serve the *same physical photo* at many different CDN URLs (different sizes, crops, cache-busting query strings, or even different hosts) — an exact-URL dedup would treat each as a distinct image, wasting a paid bg-removal call on true duplicates and cluttering the gallery/AI-curation shortlist with redundant angles. Perceptual hashing catches near-identical *content* regardless of URL, at the cost of requiring the pixels to already be downloaded (hence it runs in `select.ts`, after `extract.ts`'s cheaper URL-based pre-filter, not instead of it).

### Other pipeline-wide facts (load-bearing, not ADRs)

- **Enforced time budget, not advisory**: `core/budget.ts:capTimeout/remainingMs` clamp every downstream provider timeout to what's actually left of the route's 280s deadline (`core/budget.ts:7-15`), used throughout `enrich.ts`, `bgremove.ts`, `watermark.ts`, `discovery.ts` (indirectly) and the route's own loop-exit check (`app/api/scrape/route.ts:161-164`).
